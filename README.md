## 直播专线 VPS 到底解决什么问题

先说专线和普通 VPS 的区别。普通国际 VPS 走公网路由，晚高峰绕路、丢包都是常态；而 IPLC/IEPL 是点对点的物理专线，国内入口到海外出口之间不绕公网。MKCloud 目前几条线路的端内参考延迟是：广港 IEPL 1~2ms、沪港 IPLC 21ms、沪日 IPLC 25~28ms、沪美 IPLC 124~134ms。这些数字来自官方购物车页面标注，实际体验还要加上你本地到入口、出口到 TikTok 服务器这两段。

另一个对直播重要的点是 IP。MKCloud 每台 VPS 分配 1 个独立入口 IP 和 1 个独立出口 IP，不是和一堆账号共用一个出口。第三方测评（GitHub 上的 MKCloud 专线测评）把它“超低延迟、稳定连接、干净的 IP”列为三个核心优势，对做直播的团队来说，独立出口 IP 至少能避免“邻居违规连坐”这一类问题。

但要泼一盆冷水：官方知识库自己就写得很直白——独享 IP 不保证平台批准账号、不限流或不封号；视频播放量和账号审核问题，不是单靠买专线能解决的。专线解决的是“网络这一段”，账号资格和内容质量是另外两件事。

## 给直播推流算一笔带宽账

TikTok 直播 1080p 的推流码率常见在 4~6Mbps 上下，加上音频和余量，按 6Mbps 估算比较稳妥。

先看独享：5M 独享贴着码率下限，一个人播勉强够，但没有容错空间；20M 独享对单人直播绰绰有余，还能兼顾素材上传。如果是多间直播间共用一台，就按“路数 × 6Mbps”往上加档。

再看流量计费。以 6Mbps 推流算，上行每小时约 2.7GB；MKCloud 计量型套餐按上行+下行双向统计，账面消耗大约翻倍到 5.4GB/小时。照这个口径：

- 1TB 套餐 ≈ 185 小时直播，平均每天 6 小时左右；
- 2TB 套餐 ≈ 370 小时，每天 12 小时的日播档刚好能盖住。

注意这只是推流本身，直播中的评论加载、素材拉取也走这条线路。如果你每天播 8 小时以上，2TB 起步比较现实，或者直接考虑 10M/20M 独享，省去盯着流量表的麻烦。

共享峰值和独享的另一个差别要记住：官方明确说共享带宽是峰值，不保证持续跑满。直播对“持续上行稳定”比对“峰值速度”敏感得多，这也是为什么长时间直播场景下独享档虽然贵、依然有人买单。

## 方向怎么选：香港出口不等于美区出口

很多人以为“有香港节点就够用”，其实出口落地位置直接影响直播的观看端体验和账号环境。按目标市场分：

- 主播和受众都在东南亚、或者业务以通用出海为主：广港 IEPL 或深港 IX，1~2ms 的端内延迟，操作远程桌面几乎感觉不到卡顿；
- 做日区直播、日本市场（乐天、日本 SaaS 等）：沪日 IPLC 或沪日 IX，25~28ms 基本是本地连接的手感；
- 美区直播、TikTok 美区电商：沪美 IPLC 或沪美 IX，124~134ms 的端内延迟对推流足够，但对交互式操作能感觉到延迟。

香港出口的通用性最强，但它就是香港出口，不会变成美国或日本本地出口——这句是官方知识库的原话逻辑，别指望一条广港线搞定所有市场。

## 常见问题

**本地 OBS 推流，远程桌面连上 VPS 就会走专线吗？** 不会。官方知识库明确说，推流程序跑在本地的话，连上远程桌面不会自动把推流改走 VPS。要让流量走专线，业务程序（推流、直播相关工具）得实际运行在 VPS 里，这涉及音频视频输入的方案设计，买之前先确认自己的直播工作流能这么跑。

**独享 IP 能保证不被限流封号吗？** 不能。官方原话是“独享IP不保证平台批准账号、不限流或不封号”。独立 IP 的价值在于环境干净、不与他人共享，账号层面的风控还是取决于内容和操作。

**流量双向统计是什么意思？** 上行和下行都计入额度。直播推流是上行为主，但测试、拉流、浏览都会吃下行，预算时按双向算才不会中途停机。

**起号是不是必须独享带宽？** 官方的说法是别用“起号/主号”直接决定带宽模式，按平台规则和实际用量选就行。单人 1080p 直播、每天数小时，流量计费套餐完全够用；多路推流或 24 小时轮播，才需要考虑独享档。
